# GameTest 与隔离测试代码

参照目标版本的 [Forge GameTest 文档](https://docs.minecraftforge.net/en/1.20.x/misc/gametest/)。GameTest 在真实游戏逻辑中建立场景、按 tick 执行并断言；不能输出 GUI/渲染验收结论。这里的专服均为本机新建的隔离测试进程。

## 开发环境路径

1. 查看实际 Gradle 配置，确认有对应的 GameTest run 与测试 source set。模板没有 `gradlew` 或预设 `runGameTestServer`。
2. 按所用 Forge 版本注册测试（例如 `@GameTestHolder` / 注册事件），检查命名空间、测试名、结构模板路径与前缀。
3. 按实际配置限定测试命名空间，先跑一项已知用例验证发现/执行/失败报告，再按系统分批运行。
4. 保存测试总数、成功/失败/跳过/超时以及实际日志。零项被发现不能写为全部通过。

如果工程确实提供这些任务，可运行模块自己的 `test` 和 `runGameTestServer`。命令存在、进程完成和测试成功是不同事实；读取测试报告，不只看终端末尾。

## 发行 JAR 路径

开发环境运行不能覆盖发行包的重映射、资源遗漏、依赖打包和客户端类误加载。必要时在隔离实例加载最终运行 JAR，使用单独测试 Mod 或经过核验的测试载荷桥接。

Forge 1.20.1 的 [GameTest 启用实现](https://github.com/MinecraftForge/MinecraftForge/blob/1.20.1/src/main/java/net/minecraftforge/gametest/ForgeGameTestHooks.java)限制 production 路径；不能假设只加 `-Dforge.enableGameTest=true` 就会注册测试或出现 `/test`。先检查目标版本实际启用条件。缺少桥接时记阻塞或编写隔离辅助工具，不宣称原生路径已执行。

测试载荷须匹配候选 API、映射与依赖。记录辅助包 SHA 和来源，不修改待发布 JAR来伪装生产通过。注册后从实际命令提示/日志获取测试名，不猜模板名等于命令名。

## 断言如何有意义

- 准备场景与正式动作分离。可以预置材料，但用产品入口触发合成、交互或事件，再检查成本、输出、权限和反例。
- 异步行为使用 tick/sequence 和有界 timeout；达到全部条件后才成功，不能初始化完就调用 succeed。
- 区分游戏 tick 与墙钟；实体/区块要确实加载，网络/能力初始化完成后再读。不要用无界等待掩盖死锁。
- 断言实际权威数据：输入/输出/缓冲总量、维度、owner、状态和保存后值，避免只看 UI 缓存或方法返回 true。
- 测失败路径：拒收、空/满、保护取消、目标拆除、缺依赖、损坏数据、资源重载和重复回调。simulate 不改变状态。
- 测试失败应进入机器结果和非成功退出状态，不能只打印 ERROR 然后计为 PASS。
- 修改全局配置、随机源、玩家能力或模板外实体的用例需要清理，不与互相污染的场景并发。

## 临时测试 Mod 的边界

优先测试 source set 或独立辅助 Mod。服务端读写安排到权威线程；客户端 Screen/渲染操作安排到客户端线程。不要在同一线程阻塞等待自己执行的任务，也不要从异步线程直接遍历可变世界集合。

可观测内部状态、调用真实交互入口、建立场景和结构化记录；不能代替业务产生结果、绕过权限/成本或吞掉产品异常。若夹具绕过概率触发事件，说明实际覆盖的是事件执行链，而非自然发生概率。

FakePlayer 可测试自动化及部分事件入口，不能证明真实客户端输入、网络或多人同步。必要时让 MC Pilot 驱动真实玩家并用辅助代码断言同一场景，联合完成两端测试。

辅助端口、调试命令、测试世界和自动执行钩子不进入发布包。保留有价值的回归测试与可复现步骤；短期探针可归档，不能因为清理探针而删除唯一证据。工具可能干扰行为时，移除辅助工具做必要精简复验。
