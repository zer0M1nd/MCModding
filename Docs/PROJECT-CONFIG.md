# 项目配置与可覆盖策略

这是使用者定制模板的主要入口。**当前为未初始化产品的模板配置**；“默认”是以后开发的起点，不是已经安装、已经验证或已经获准对外发布的事实。用户明确的新要求优先，修改政策时同步对应专题，避免并存两套冲突规则。

## 身份与技术

| 项 | 初始值 / 填写方式 |
| --- | --- |
| 项目名称、modid、包名 | 待实际项目确定；`ExampleMod` / `examplemod` 仅示意，不自动成为产品身份 |
| 工作类型 | 待确定：原创 / 移植 / 附属 / 兼容扩展 |
| Minecraft / 加载器 | 文档默认示例 1.20.1 / Forge；实现前填写精确 Loader 版本 |
| Java | 默认示例 Java 17；以所选 MC、Loader 和构建插件要求为准 |
| Gradle / 构建插件 / 映射 | 未安装；建工程后固定精确版本，记录 mapping 命名体系 |
| 产品版本 / 已发布版本 | 无；候选编号参考 VERSIONING，不虚构已发布稳定版 |
| 模块及依赖图 | 当前仅 ExampleMod 文档；新增实际模块时登记 Code、Docs、Sessions 位置 |
| 参考基线 / 源码来源 | 待确定；每个原包、分支和必要依赖记录版本、来源、哈希及许可 |
| 公共 API / 存档 / 配置兼容 | 默认保护已承诺的兼容性；首次实现前写明具体版本范围与迁移策略 |
| 产品许可证 / 第三方素材许可 | 由维护者选择与核实；本模板不替未来产品授予第三方资源许可 |

## 默认政策

| 政策 | 默认值 | 更改时同步 |
| --- | --- | --- |
| 移植目标 | 可玩性优先、核心玩法与风格保留、现代原生机制优先、明确缺陷修复 | PORTING、模块 SPEC、变化记录 |
| 版本规则 | `w.x.y[.z]`，日常 Agent 只递增 z | VERSIONING、元数据、比较器和交付说明 |
| 代码布局 | `Code/<模块>/`；初期可以使用单一根 Git 仓库 | WORKSPACE-RULES、模块入口 |
| 文档布局 | 统一 `Docs/`；模块状态和规格分开 | START-HERE、CURRENT-STATE |
| 测试范围 | 开发/修复任务包含影响范围内的必要隔离验证；用户当次限制优先 | TESTING、任务测试计划 |
| 客户端操作 | 只操作本任务隔离客户端，静音并减少焦点干扰；用户排除客户端测试则不启动 | 任务计划与报告 |
| 测试辅助 Mod | 可按需装入隔离实例，记录来源、版本、哈希和安装侧 | 测试 manifest |
| 发布 | 默认本地交付。外部渠道未配置、未授权；不自动创建远程仓库或上传 | RELEASE、任务范围 |
| 持续更新客户端 | 空列表。使用者显式登记后才启用；只更新已安装的授权 modid | RELEASE、本机配置 |
| 多 Agent | 默认单 Agent；协作时优先随附工具，一个资源一个写入者；无工具才人工串行协调，也可自主编写工具 | CONCURRENCY、CLAIMS |
| 美术流程 | 独立像素材质用 Aseprite；模型/UV 用 Blockbench；无已安装假设 | VISUAL-ASSETS |

实际设备路径、账户及本地安装列表放被 Git 忽略的 `Local/`，公共文档只引用其用途或配置键。不要将私密值填入本文件。

## 当前任务覆盖记录

尚无产品任务覆盖。后续使用以下字段记录必要差异：任务 ID、用户要求、影响范围、替代的默认规则、开始/结束条件、需要同步的文档。一次性的“不测试”不能变成永久项目默认；一次验收也不能追认历史所有版本。
