# 通用开发陷阱与回归方向

以下从长期移植、联动和测试工作中抽象而来，不包含具体项目的问题清单。它们是排查线索，不代表每个 Mod 都有这些缺陷。发现相似症状仍要在当前实现中确认根因。

## 业务、数据与生命周期

| 常见陷阱 | 正确处理与最低回归 |
| --- | --- |
| 只迁移注册，配方、获得、菜单或同步留占位 | 按玩家完整链路验收；能在创造栏拿到不等于生存流程可用 |
| 把“请求转移量”当作“实际接受量”扣除 | 模拟只是预估；按真实提取/交付记账，拒收返还或持久化缓冲。测满容器、部分接收、拆除与重载 |
| 失败先扣物品/能量，或先删实体再生成产物 | 验证可执行条件，提交时处理失败/补偿；测保护事件取消、空间不足、创建失败及连续重试 |
| 查询/预览/simulate 改变状态 | 查询保持无副作用；真实成功操作才付款。重复查询前后比较库存、耐久、能量和经验 |
| 只在 GUI 限制按钮/数量，服务端相信客户端 | 权威端复核索引、距离、权限、模式、材料和成本；测非法包、快速连点和过期菜单 |
| 只锁普通点击，漏掉 shift、数字键、副手交换 | 覆盖所有容器操作入口，验证持有物身份和 stillValid；重开菜单检查无复制/丢失 |
| 整个物品 NBT 被功能字段覆盖 | 只更新自己负责的子数据；测名称、附魔、其他 Mod 数据和容器载荷保留 |
| 匹配原料用贪心算法，标签重叠时失败 | 对多种可替代材料做一对一匹配，保证预览计划、真实扣料和展示来自同一结果；测通用/专用材料竞争 |
| 缓存只按物品 ID，不含 NBT/配置/数据重载 | 根据实际语义建立键和失效策略；测同物品不同数据、重载与连续查询，不每次重建全表 |
| 长期持有失效能力/实体/世界引用 | 监听失效或在操作前验证生命周期，按世界实例隔离；测拆除替换、卸载、退世界再进入 |
| 相同网络作为自己的外部存储 | 检查递归回路与重复计数；测自接、双向连接、环路、网络拆分重连 |
| 保存只覆盖正常流程 | 保存进行中交易、已付费用、冷却和持久缓冲；重启不重复领取、重扣费用或丢进度 |
| 静态全局表跨存档/维度残留 | 使用世界级数据或明确清理，稳定身份使用 UUID/资源键；测退出、换维度与重载 |
| 异步保存/遍历可变游戏对象 | 在正确线程取一致快照，再进行必要异步工作；检查并发修改异常和漏存 |
| 损坏/未知存档一律清空 | 明确字段版本和恢复策略，保留可恢复未知数据，报告不支持项；测试缺字段、异常数值、未知 ID |
| 配置默认值等于显式选择 | 区分缺省、继承和显式覆盖；升级补全新字段但保留旧值。检查配置作用域、真实文件与加载时机 |

## 现代 Minecraft 适配

| 常见陷阱 | 正确处理与最低回归 |
| --- | --- |
| 用 int 强转方块坐标或用负 Y 当无效标记 | 使用正确的向下取整与显式“无位置”；测负坐标、现代最低高度和维度身份 |
| 整数乘法溢出、零距离归一化、周期变零 | 容量用合适类型和有界运算；拒绝非有限值，处理零向量。测极端 NBT、满容量和高等级 |
| 保留旧 AI 的每 tick 重寻路或任务重复安装 | 复用适合的现代 Goal 并保留专有约束；重配置清理旧任务。测目标切换、路径失败、抵达、卡住和重载 |
| 直接改方块绕过原生交互和保护事件 | 使用对应玩法入口，处理 Forge/原版取消与掉落；测创造/生存/旁观、权限和不可破坏目标 |
| 只搬移门、床或乘骑关系的一半 | 识别关联结构或拒绝部分搬移；检查完整载荷、朝向、原位置清理与失败回滚 |
| 在不加载区块的查询里意外强加载 | 先核对已加载状态；用明确任务控制加载生命周期，结束后清理强加载 |
| 可选依赖类出现在公共初始化或静态字段 | 在真正侧别/依赖条件下隔离类加载；测试无依赖启动和专服启动，而不只测完整开发环境 |
| 参考错 Minecraft/Loader/API 版本 | 固定精确版本并查实际方法签名；遇到 NoSuchMethodError 先核对运行 JAR，不一味换“最新版” |
| 公共 RenderType/方法签名变了但附属未重建 | API 改动认领全部受影响模块；保留桥接或明确兼容破坏，并验证已发布调用方组合 |
| Mixin 在开发可用，发行环境失败 | 核对目标类、描述符、remap/refmap、访问方式与打包重映射；实际运行发行 JAR |
| DataGen 覆盖手绘资产，生成资源没入包 | 分离 main/generated，检查 sourceSets 和重复路径；检查最终 JAR 条目，不只看工作树 |
| Windows 能加载大小写错误资源，其他平台失败 | 资源 ID 用合法小写，文件路径精确匹配；检查动画 `.mcmeta`、模型引用和命名空间 |

## 渲染、输入与测试本身

| 常见陷阱 | 正确处理与最低回归 |
| --- | --- |
| 事件收到了、数值正确就说特效正常 | 查看真实画面。效果可能在后续帧缓冲/合成/剔除阶段丢失 |
| 直接换 shader/RenderType 修复一种光影 | 顶点格式、混合、深度、排序与阶段一起核对；测试原生、关光影、开光影、透明遮挡和资源重载 |
| 修改全局 blend/depth/matrix 后不恢复 | 局部拥有并恢复状态；检查天空、暗角、手部、邻近物体和下一帧，不只看目标物 |
| 相机矩阵、GUI 坐标、世界坐标混用 | 使用正确坐标空间；测相机旋转、窗口缩放、负坐标和视角变化 |
| 自动化直接调用业务方法，绕过待测点击 | 鼠标命中、键盘焦点、拖动问题走真实 Screen 输入；方法级测试只能报告相应覆盖 |
| 只放置目标物截图，没完成实际制作 | 管理命令仅准备输入；实际合成/使用由玩家路径触发，双端核对成本和结果 |
| GameTest 未注册/零执行却当成功 | 先核对发现数量并跑自检用例；验证失败确实进入报告 |
| 异步断言过早 succeed，或夹具目标没加载 | 使用 tick/sequence 和前置条件，延后成功；记录是夹具修正还是产品修复 |
| 用旧 PASS、旧 manifest、旧脚本输出目录 | 每轮唯一 ID/日志范围/候选 SHA；实际读取世界种子和加载清单，执行脚本前检查硬编码路径 |
| 超时立即重发非幂等动作 | 查询现场再决定是否重试，避免自动化自己造成重复消耗/产出 |
| 录像或 profiler 引入卡顿被当作产品 Bug | 同场景预热，加入不录制/无探针对照；区分 tick、帧和网络时间，不凭单帧 FPS 下结论 |
| 只在优化器“关闭效果”状态测试 | 未安装优化器可能是不同加载和渲染路径，需单独覆盖 |
| 测试辅助类或调试权限混进发行包 | 构建与工具源码隔离，审阅 JAR 条目，检查发行依赖和自动执行开关 |
| 把历史局部通过累加成全量通过 | 每条证据绑定候选、环境和范围；独立统计用例/断言/图片，不累计重复重试 |

## 工作区与交付

已有未提交改动不是“垃圾”；清理状态不能使用破坏性 Git 操作。共享 build 与旧一次性脚本容易污染别人的运行环境，认领也必须覆盖生成目录、依赖和测试实例。

文件名不等于 modid/版本，启动器可能使用版本隔离目录。同名新 JAR 也可能是旧内容，复制前后都核对元数据与哈希。安装列表为空不代表应自动新增所有附属。

来源索引缺少一个文件，不足以证明原作者删除；依赖解析失败应区分镜像索引、真实下载、版本范围、缓存和网络问题。保留具体失败层的证据，不把改下载源当成兼容性修复。

缺少许可证、出处或复用许可的素材不能因为“网上可下载”就随包发布。资料、原包、源代码和改造后资源各自的分发边界须单独核对。
