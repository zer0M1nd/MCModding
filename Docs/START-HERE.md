# 新会话入口

先读根 [AGENTS](../AGENTS.md)，再读 [工作区约定](WORKSPACE-RULES.md)、[项目配置](PROJECT-CONFIG.md)、[当前状态](CURRENT-STATE.md) 和涉及模块的 CURRENT。不要开局遍历全部历史文档或沿用上一会话的“已完成”。

## 第一次建立项目

1. 从用户需求确定 modid、名称、目标 Minecraft/加载器/Java 版本、玩法目标和交付范围，写入 PROJECT-CONFIG。普通实施细节可自主选择并记录；只有影响目标的缺失信息才需要询问。
2. 明确这是原创 Mod、跨版本移植还是附属。移植指定原作者版本、参考分支、资源许可与兼容承诺；附属指定宿主 API 和必需/可选依赖。
3. 将 `ExampleMod` 示例改成实际模块，建立模块 CURRENT 与 SPEC，保留 Sessions 入口对中央文档的显式引用。
4. 按 [认领入口](Coordination/CLAIMS.md) 优先使用可用工具，一次认领本轮唯一 owner 所需的全部资源，再创建实际代码工程。没有工具才手动串行协调。原始模板不包含 Gradle Wrapper、JDK、GameTest 注册或 MC Pilot 驱动。
5. 按目标版本的官方入门资料建立工程，先验证加载和基本资源，再按完整系统开发。命令必须从实际构建配置获取。

## 继续已有任务

从 CURRENT 找到当前候选、未完成范围、相关报告和认领。核对 Git 工作树、依赖和候选哈希；若现场已经过期，保留历史结论并重建必要环境。只读取影响当前决策的规格、源码和旧证据。

当前任务被暂停、要求不启动客户端或留下手测现场时，保留这些条件；状态恢复以新指令为准。新消息通常是补充或修正当前目标，不应自动丢弃尚未完成的任务。
