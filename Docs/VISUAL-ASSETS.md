# 材质、模型与 GUI 制作

创建或修改前先读本文件与 PROJECT-CONFIG 中项目指定的美术要求。确定 Minecraft 版本、Java/Bedrock 平台、渲染方案、用途、分辨率、风格和许可。模板没有预装美术软件、MCP 或技能。

## 工具分工

| 工作 | 默认工具 | 验证 |
| --- | --- | --- |
| 独立物品/方块像素材质 | Aseprite，可用其原生脚本/批处理 | 尺寸、alpha、调色板、缩放与拼接 |
| 物品/方块/实体模型 | Blockbench，格式匹配项目实际运行管线 | 朝向、原点、旋转、UV、各显示变换 |
| 模型表面绘制、UV | Blockbench 纹理工具，必要时配合 Aseprite | UV 对齐、拉伸、接缝与动画 |
| GUI/HUD | 游戏自己的布局与渲染体系；资源用合适的二维工具 | GUI 缩放、焦点、溢出、可点击区域与翻译 |

使用 Blockbench MCP 时先读取当前可用的工具/技能说明，检查活动格式与项目；不能假定本机工具名或端口固定。Java 普通方块/物品可用相应 Java 模型格式；实体与自定义渲染模型按实际加载方案选格式，不统一导出为普通 JSON，也不误用 Bedrock 格式。

## 先复用，再改造

优先查找项目内、原版或许可允许的已有材质，通过换色、重组和局部调整达到目标。例如新金属锭先以已有合适金属锭的形体与明暗为基础，再调整颜色和细节；引用原版资源时优先资源路径，避免不必要地复制受限资产。

保留可编辑源文件和来源说明。每项外部资产记录来源、版本、许可/署名、改动、输出路径与哈希；可读原包不等于可以打包其素材，变色也不会消除原许可要求。

确有需要才从零绘制。AI 生成图片可用于概念与适合的位图资产，但应经过像素尺寸、透明度、风格和游戏内效果审核，不能直接把概念图当作已实现的游戏截图。

## 导出与验收

资源使用正确命名空间、小写路径和目标格式；动画帧布局与 `.mcmeta` 对应，模型贴图引用与 BlockState 变体完整。手工资源与 DataGen 输出不共用同一资源路径。

在真实客户端看物品栏、手持、掉落、方块各面、明暗/遮挡、必要动画与 GUI 缩放；相关复杂模型按需旧版对照。外部编辑器预览不能代替游戏验收。规则与工具见 [TESTING](TESTING.md) 和 [CLIENT-TOOLS](Testing/CLIENT-TOOLS.md)。

字体与断行优先现代原生实现，保持结构和可读性；不默认复刻旧字体的每个像素。视觉问题修复后重载资源或重启实际候选，确认没有使用旧缓存，并记录真正看过的截图/录像范围。
