# 模板整理说明与验证

整理日期：2026-11-07。用途：为新的 Minecraft Mod 项目提供可定制、可由 Agent 接续的工作区。

## 提炼依据

本模板综合了既有开发工作区的当前流程、统一测试方案、版本协议、并发约定，以及与测试方法演进、现代化移植、版本语义和典型故障有关的开发对话/验收记录。采用定向阅读，并非对全部历史对话逐轮完整审计。

当前规则优先于历史限制：客户端驱动采用游戏接口优先的方案；迁移采用可玩性和现代原生机制优先的目标；版本沿用可修改的三段/四段协议。历史经验被转化为触发条件、根因、工程不变量与验证方法，不复制特定产品的内容清单。

## 泛化与排除

- 以通用目录、示例模块、逻辑资源名替代实际机器和项目名称。
- 不携带账号、密码、密钥、内网地址、设备目录、聊天原文、实际会话标识或私有源码/资源包。
- 不包含服务器运维、定时部署、远程连接或群聊功能。服务端内容限本地隔离测试，保留独立进程/网络路径的必要验证概念。
- 本地客户端持续更新改为可选策略，初始清单为空，不沿用原工作区安装目标。
- 仅随附多 Agent 协调工具和其测试；优先使用可用工具，无工具才手动协调，允许 Agent 按协议自行编写工具。
- 文档中的技术版本是示例或已注明的历史基线，没有宣称为最新版本，也没有宣称已安装游戏环境。

## 本次验证

协调工具在 **Windows / Python 3.14.0** 下执行 13 项测试，全部通过。测试在系统临时目录运行，不使用真实开发认领表。覆盖：

- 状态只读、大小写归一、幂等认领、完整释放。
- 批量申请冲突不留下部分占用，错误 owner 无法释放其他人的资源。
- Layout 双向全局互斥，原子交接及禁止拆分 Layout 归属。
- 损坏/重复键 JSON 拒绝写入，认领不随时间自动失效。
- 残留事务不被抢占；实际强制结束事务子进程后，旧状态保持且新写入被阻塞。
- 8 个进程竞争共享资源只有一个成功，8 个进程申请独立资源全部保留。

执行入口：

```text
python -B -m unittest discover -s Tools/Coordination -p "test_*.py" -v
```

文档核验涵盖内部相对链接、代码围栏、JSON 示例、UTF-8 文本、文件类型与隐私残留；公开文档主要入口已抽查。没有运行 Minecraft、GameTest、MC Pilot 或 Mod 的单元/客户端测试，没有构建或发布任何 Mod。

跨平台和网络文件系统行为未实测。工具只提供合作式本地认领，不是身份认证、操作系统写入权限或分布式锁；当前环境的并发测试不等于所有故障条件下的数据持久性证明。

## 使用者需要确定的事项

填写 [项目配置](PROJECT-CONFIG.md)，选择实际 modid、平台版本、许可和玩法目标；按需求建立代码工程与隔离测试环境。版本、兼容、美术和验证政策都可以通过明确要求修改，需同步入口和相关专题。模板中不存在假定已通过的产品测试或已发布稳定版本。
