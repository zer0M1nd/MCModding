# 多 Agent 协作协议

适用于同一工作区的多个会话、主 Agent/子 Agent 及多人协作。是否启用子 Agent 遵循当前用户要求和运行环境；本协议不是自动授权创建额外会话的要求。

**有可用的认领工具时优先使用工具；没有适配工具时才手动协调。** 本模板提供 [claims.py](../Tools/Coordination/claims.py)，仅依赖 Python 标准库。Agent 可以按本协议自主编写或改进工具，先验证关键并发与故障行为，再启用。

## 资源与单写入者

| 资源 | 保护范围 |
| --- | --- |
| `module:ExampleMod` | 模块源码、资源、构建目录、生成目录、依赖快照及模块专属文档 |
| `Docs` | 共享规则、全局状态、跨模块报告和模板 |
| `Publish` | 同一批交付产物、共享发布记录、已授权的本地安装目标 |
| `BuildCache` | 共享缓存删除/迁移；普通 Gradle 依赖缓存由其自身锁协调 |
| `Layout` | 全局目录调整及协调工具/认领机制的修改；与其他 owner 的所有认领互斥 |
| `test:<run-id>` | 同轮世界、实例、控制端口、日志和测试进程 |

同一资源只有一个 owner。不同 owner 可并行处理不同模块；共享 API 或依赖更新一次认领全部被写模块与共享资源。工具按资源名协调，不自动发现文件冲突；必须由 Agent 如实申报完整范围。

一个模块不能因为有两个 worktree 就变成两个写入者。需要同模块拆分写入时，先明确新的互斥子资源边界、集成 owner 和构建隔离方案；未完成这一步时，其他 Agent 仅提供只读审查。共享规则由协调者合并，避免各 Agent 重写全局 CURRENT。

## 工具模式

从工作区根目录运行；owner 使用本轮唯一会话 ID，下例名称仅示意：

```text
python Tools/Coordination/claims.py status
python Tools/Coordination/claims.py claim --owner agent-a --task "实现一个完整系统" --resources module:ExampleMod Docs test:run-a
python Tools/Coordination/claims.py check --owner agent-a --resources module:ExampleMod Docs test:run-a
python Tools/Coordination/claims.py release --owner agent-a --resources module:ExampleMod Docs test:run-a
```

查看状态后一次性认领；冲突时整次失败，不保留本次申请的一部分。获得认领后再改文件、构建或启动游戏。工具名大小写不造成两个资源：资源名统一小写比较。

所有参与者必须使用**同一个实际状态目录**。默认是本工具所在工作区的 `.coord/`；跨 worktree 时明确传入同一个 `--state-dir`，不能各用本地副本。状态目录放可靠的本机文件系统，不放异步网盘同步目录；本工具不承诺跨机器分布式锁。

认领持久保存，不按时间自动过期。短事务使用独占目录与原子替换保存状态。锁等待超时、Agent 无响应或构建进程退出，都不是抢锁理由。完整使用与恢复见 [工具说明](Coordination/TOOLS.md)。

## 任务拆分与交接

协调者先明确各 Agent 的目标、写入资源、接口契约、基线、验收条件和交付路径，使用 [Agent 任务模板](Templates/AGENT-TASK.md)。执行者不得扩展到未认领模块或升级冻结依赖。

冲突时只读调查，整理可合并建议或处理无冲突任务。需要联系其他会话时遵循当前平台对消息发送的授权，不通过清锁冒充协调。

交接前记录：改动文件、Git 状态、候选哈希、实际验证、失败、待办、需保留的现场。停止占用构建/运行目录的相关进程，或明确将整个现场一并交接。使用原子 `handoff` 把指定资源交给已约定的 owner，或由原 owner 释放后重新认领；不能用旧 owner 的身份继续写入。

主 Agent 对最终集成负责：检查接口与依赖一致性，重新冻结集成产物，执行受影响的跨模块用例，再交付。各子模块单独通过不等于集成通过。

## 无工具时的手动模式

只有确认没有可用协调工具时才启用 [人工认领表](Coordination/CLAIMS.md)。先指定唯一协调者，所有认领请求由它串行写表并明确确认后才生效。各 Agent 不得同时编辑表格或凭“我先看到了空闲”获得写入权。

纯 Markdown 不提供原子性；没有可靠串行协调者时停止并发写入，改为单 Agent 工作或先实现工具。工具恢复后先暂停新写入，把人工有效认领一次迁入工具并逐项核对，再宣布工具为唯一状态真源；不能同时维护两个独立认领表。

## 自编工具的最小契约

须支持只读状态、批量全有或全无认领、owner 校验、持久认领、显式释放、Layout 全局互斥、短事务原子写入、损坏状态拒绝继续及无自动抢锁。建议提供原子交接、机器可读 JSON 和固定退出码。

测试同资源竞争、不同资源并行、部分冲突、错误 owner 释放、进程中断遗留事务、状态损坏和交接。工具是协作协议实现，不是操作系统权限或身份认证，不能宣称它阻止所有非合作写入。
